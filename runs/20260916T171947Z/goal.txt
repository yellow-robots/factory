In `builder.py`: any path with a `.git` component at any depth is not part of the checkout, refused by every tool as `not part of the checkout` and left out of listings, as `.git` at the root already is; a listing keeps naming its entries by their path relative to the checkout root, as it has since v0.1. `numbers.json` carries `written` and `edited`, the paths the tools wrote and edited in order, so the record names every file the run touched whatever git lists, and the numbers line carries them too. The diffs of `record_diff` run with `--text` as well, so an attribute cannot turn the patch into a binary notice. `git_env()` sets `LC_ALL` to `C`, so git answers in English, and the not-a-checkout test reads the first line of git's stderr after `fatal: ` and nothing else. The refusal the model reads for a protected path says `protected: <path> (not the builder's to change: the tests, the toolchain, the vault and git's own files)`. The tests in `test_builder.py` whose docstring names this seed define the behaviour; `check.Dockerfile`'s comments say checkout, by the attended agent.
