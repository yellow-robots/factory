## it-36 slice I — what shipped is published

Every PR carries its publication input under a declared manifest key, an iteration ships as a
release with machine-readable notes, and every registered stakeholder is told: the merge evaluator
gains a `fragment_present` condition (a deterministic changelog fragment the implement stage writes
under the manifest's `changelog_dir`, or the attended lane's own duty); `tools/release.py` gains the
`it/<n>` iteration-release family beside the skill family; `tools/changelog.py` compiles fragments
(or a merged PR's own title, named as such) into `CHANGELOG.md` and a release body carrying a fenced
`yr-changelog` block; `tools/notify.py` delivers that release to the manifest's `[[stakeholders]]`
table — telegram/webhook (signed), issue-comment, or github-release — then posts `YR-CHANGELOG`
naming the delivered set. This fragment is itself the attended lane's own duty, dogfooded (N3, cold
review of #474): an untyped attended slice carries no run dir for the runner's own implement stage
to write one, so it is added by hand.
