# v0.2: the observer on pydantic-ai

The loop borrowed, pinned and read once on the wire; the plane, the role and the record kept.

## Changelog

- pydantic-ai-slim[openai]==2.43.0, 28 packages locked. The report comes back through the
  `final_result` function as a typed four-field object, rendered to the same four sections.
- The record grows: `wire.jsonl` with every HTTP attempt, headers with secrets redacted, full
  bodies; `messages.json` with the library's history; numbers add library, wire attempts,
  reasoning tokens, cost source.
- Read on the wire: the system message is byte-identical to the role; the library adds
  `tool_choice: auto`, `stream: false`, the `final_result` tool, the SDK's headers, and passes
  DeepSeek's `reasoning_content` back on tool turns. The stock DeepSeek profile would force a tool
  choice the API rejects for `deepseek-flash`; a profile override keeps `tool_choice: auto`.

  a line longer than the byte cap is cut instead of dead-ending a read; symlink loops are error
  strings; `.venv` and `plans` hidden from the world alongside `runs`, `.claude`, `__pycache__`.
- Same goal as v0.1: 4 requests, 6 calls, 701 lines, $0.007, 18.5 s; the escape probe made one
  out-of-world attempt in 7 calls and reached nothing hidden.

# Factory v0.2: the observer rebuilt on pydantic-ai

## Context

v0.1 (`/opt/yellow-robots/factory`, `main` at bc8eac0) is an owned loop of ~300 lines: fixed role
text, two confined tools (`list`, `read`), DeepSeek over raw HTTP, a run record (`transcript.jsonl`,
`response.md`, `numbers.json`). It ran on its own directory twice and once under an adversarial
goal; the role held, the plane held, and one gap surfaced: the nested worktree
`.claude/worktrees/bootstrap/runs/` was readable because hiding applies to the first path segment.

The owner's direction: do not build loop machinery from scratch; own the plane and the roles, borrow
the loop from a library reviewed by many, pin it, read once what it adds. Pick: **pydantic-ai**.
v0.2 is the observer rebuilt on it: same plane, near-identical role text, a typed four-field report,
the same caps, run on the same goal and model as v0.1, compared against the v0.1 run. The swap is
paid for when the differences are noise; if the library's additions change behaviour, it shows on
one run before anything is built on top.

Self-contained version: a cold agent gets this plan and the repository, nothing else.

## Facts established (research, 2026-09-15)

- **Package.** `pydantic-ai-slim[openai]==2.43.0` (released 2026-09-12; v2.0 was 2026-06-23).
  Core deps: `pydantic>=2.12`, `pydantic-graph`, `httpx2>=2.7` (Pydantic's httpx fork), `anyio`,
  `genai-prices`, `griffelib`, `opentelemetry-api`; the extra adds `openai>=3.8.0`, `tiktoken`.
  Python >=3.10 (host has 3.12, uv 0.8.0). Docs live at `https://pydantic.dev/docs/ai/`.
- **Model.** `OpenAIChatModel('deepseek-flash', provider=DeepSeekProvider(api_key=..., http_client=httpx2.AsyncClient(...)))`.
  Settings via `OpenAIChatModelSettings` (`temperature`, `seed`, `timeout`, `thinking`, ...).
- **Model name.** `deepseek-flash` is the current name and is served by DeepSeek-V4.1-Flash; the
  legacy `deepseek-v4-flash` is still accepted but retired (same model, Flash price). We use
  `deepseek-flash`, as v0.1 did.
- **Gotcha 1.** pydantic-ai's DeepSeek profile keys on the name string and treats only
  `deepseek-v4-*` as V4. For `deepseek-flash` it will therefore send a forced `tool_choice` for the
  output tool while the API has thinking on by default, which DeepSeek rejects with HTTP 400
  ("Thinking mode does not support this tool_choice"). Fix, in order of preference: pass a merged
  `profile=` marking the model as thinking-capable with
  `openai_supports_forced_tool_choice_with_thinking=False` (tool choice becomes `auto`, thinking stays
  at the API default exactly as in v0.1, so the comparison isolates the library swap); fallback
  `thinking=False` in model settings if the model then answers in text more than the output retry
  budget tolerates.
- **Gotcha 2.** genai-prices has no `deepseek-flash` row, so `result.usage().cost` is `None`; keep our
  price table as fallback and record which source produced the number.
- **Instructions.** `Agent(instructions=ROLE)`; instructions are re-sent each request and not stored
  as a message part (`system_prompt` would be). Nothing is appended to them in tool-output mode.
- **Tools.** `Agent(tools=[Tool(fn, takes_ctx=False), ...])`; schema from type hints + docstring
  (google/numpy/sphinx via griffe). Invalid arguments become a retry prompt to the model (budget
  `retries={'tools': 1}` default; exhaustion raises `UnexpectedModelBehavior`). Unknown tool name
  → retry prompt "Unknown tool name: ... Available tools: ...".
- **Output.** `output_type=Report` (BaseModel) defaults to **tool output**: a synthetic tool
  `final_result` whose description is the model's docstring and whose parameters are its JSON schema;
  `tool_choice` forced to it when the profile allows. Plain text instead → retry prompt "Plain text
  responses are not permitted, please call one of the functions instead." (budget `retries={'output': 1}`).
- **Limits.** `UsageLimits(request_limit=50 default, tool_calls_limit=None, total_tokens_limit=None,
  cost_limit=None, ...)`; hitting one raises `UsageLimitExceeded`; no result survives, but messages
  do inside `with capture_run_messages() as messages:`.
- **Record.** `result.all_messages_json()` (pydantic-level); `result.usage()` → `RunUsage(requests,
  tool_calls, input_tokens, output_tokens, cache_read_tokens, cost, details, ...)`,
  `cache_hit_ratio()`. DeepSeek's `prompt_cache_hit_tokens` maps to `cache_read_tokens`.
- **Wire.** The library's hooks see pydantic-level messages only; raw request/response bodies come
  from `httpx2` `event_hooks={'request': [...], 'response': [...]}` (async hooks; `await
  response.aread()` for the body). The openai SDK retries 429/5xx twice on its own; `RunUsage.requests`
  counts logical requests, the wire log counts attempts.
- **Tests.** `FunctionModel(fn)` with `fn(messages, info) -> ModelResponse`; `TestModel`;
  `models.ALLOW_MODEL_REQUESTS = False`; `agent.override(model=...)`.
- **Retry text the library injects** (for the record): validation errors render as "N validation
  error(s): ```json [...] ``` Fix the errors and try again."

## Decisions (recommended; strike any you disagree with)

1. **Plane errors stay tool results, not retries.** `outside the world`, `not a file`, etc. return
   `error: ...` strings exactly as in v0.1, so a probing model can keep probing and every attempt is
   recorded. Only argument-shape errors (wrong types) use the library's retry path.
2. **Cap hit = failed run, no forced report.** `UsageLimits(tool_calls_limit=40, request_limit=60)`.
   On `UsageLimitExceeded` the run records `stopped=cap`, keeps the messages via
   `capture_run_messages`, writes no report. Cleaner signal for evals than v0.1's "write it anyway",
   and avoids driving `agent.iter` by hand. Behaviour change vs v0.1, noted in README.
3. **Thinking at the API default, temperature 0, output retries 2.** Same request shape as v0.1 so
   the parity run measures the library swap only; gotcha 1 handled by the profile, not by disabling
   thinking. Reasoning tokens, when DeepSeek reports them, are recorded from `usage.details`.
   `thinking=False` is the documented fallback and, if used, is recorded in numbers.
4. **Output via the `final_result` tool** (library default). The role text changes minimally: the
   four sections become the four fields of the report the model returns through `final_result`,
   with the same descriptions. The role hash therefore changes; expected and recorded.
5. **The world hides three names** at its root: `runs` (the record), `.claude` (harness scratch),
   `__pycache__` (bytecode from running tests). Everything else, `.git` included, stays visible.
6. **Remove the nested worktree** `.claude/worktrees/bootstrap` (branches `bootstrap` and `v0.1` are
   both mirrored on GitHub) after copying its first-ever run `runs/20260915T085903Z` into the main
   checkout's `runs/`. Closes the gap the adversarial run found at the source, not only by hiding.
7. **Dependencies via `pyproject.toml` + `uv.lock`**, pinned `pydantic-ai-slim[openai]==2.43.0`; run
   with `uv run`. Tests stay on `unittest`; no pytest.
8. **Keep our wire log permanently.** `wire.jsonl` is the truth of what was sent; the library's
   `messages.json` is a rendering. Both are written every run.
9. **Tag** `v0.1` at bc8eac0 now and `v0.2` at the end. Tags are derived state kept by git.

## Considered and not used in v0.2: `pydantic-ai-harness`

First-party companion package (0.31.0, 2026-09-12; MIT; `pydantic-ai-slim>=2.40`). Fifty-plus
composable capabilities: `FileSystem(root, read_only=...)` with read/write/edit/search tools and
path-traversal/symlink safety, `Shell` with allowlists, `RepoContext` (injects `AGENTS.md`/`CLAUDE.md`
and repo structure), `Planning`, `Memory`, `SubAgents`, `Compaction`, guardrails, and the prebuilt
`Coder` and `Researcher` agents. Each capability is usable alone via `Agent(capabilities=[...])`.

Not used now, for three reasons:

- **It is the stack v0.1 deliberately did not assume.** Shell, repo-orientation prose, planning
  files and memory are exactly the capabilities and narrated state we removed; the factory grants
  one function per version and measures it. Nothing in the harness is off the table forever, but
  each piece enters only when a version's goal needs it.
- **The plane is the factory's design surface, not plumbing.** What the model can do to the world,
  how results are shaped (numbered lines, truncation continuation), what is hidden, and what is
  counted are the thing under study. v0.2 changes one variable, the loop; swapping the plane in the
  same version would blur the comparison.
- **0.x versioning**: APIs move between minor releases, three months after pydantic-ai 2.0. The core
  library carries the stability pledge; the harness does not yet.

Where it does earn a look, as its own version: `FileSystem(read_only=True)` against our two functions
on the same goals, judged by the runs (its path safety is reviewed code for exactly what we
hand-wrote), and later `FileSystem` write/edit when a version first needs a write, since atomic
edits, encoding and size limits are where reviewed code beats ours. `RepoContext`, `Planning`,
`Memory` and `Coder` stay out on principle, not on maturity.
