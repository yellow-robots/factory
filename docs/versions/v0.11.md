# v0.11: the set with a pass rate, the tool errors counted

The evaluation table gains what a comparison between two runs of the set needs: each case declares the outcome that is a pass, the table counts the runs that reached it and prints the set's pass rate with its standard error, so a rise is told from noise; and the tool returns that were the model's lapses and not a wall's refusal are counted per run in both tables.

Two seeds, from the owner's questions of 2026-09-17. Built by the factory from the attended agent's tests; the nine pass words are the attended agent's, like the tests.

## Changelog

- Each case declares the outcome that is a pass in `cases/<name>/pass.txt`, one word: `green`, a run whose check ended green; `red`, an honest run whose check ended red; `refused`, an honest red that wrote and edited nothing; a case without the file, with another word or with one that is not UTF-8 is not whole. `evals.py` counts in `passed`, right after `refused`, the runs that reached the word, and prints after the table the set's pass rate, the mean over the cases of the proportion of runs passed, with its standard error, the square root of the sum over the cases of n/(n-1) times p(1-p) over the square of the case count, the owner's estimator of 2026-09-17 with the small-sample correction; the rate alone with one run per case. The word is the harness's: 85 of the 99 records showed the model reading `cases/` in its worktree, so `builder.main` takes `hidden`, the names a caller adds to the builder's own hidden ones, and `evals.py` passes `cases` for every run it starts; the builder's five hidden names are unchanged. Over the two set runs already on file the built code gives v0.6 a pass rate of 0.778 with standard error 0.091 and v0.7 0.963 with 0.064, the seed's hand count for v0.7 to the digit and v0.6 corrected from 8.0 of 9 to 7.0; the difference is 1.7 standard errors of the difference, so the rise is still not shown. A column `tool_errors` in both tables, right after `checks`: a run's tool returns that start `error:` and are no wall's, neither a refusal nor a cap reached nor a check without a sandbox, the model's lapses, an anchor that missed or a path of the wrong kind, counted by one function in `runs.py` that `evals.py` reads too, the median over a case's runs in the evaluation table and the count per record in the runs table; the refusal prefixes moved to `runs.py` with it. Over the set runs on file the median is 0 to 3 per case.
