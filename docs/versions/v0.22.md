# v0.22: fewer requests, and the loop counted

The day v0.21 shipped, two thirds of what its builds spent went to runs that read and never wrote: 20 builds, $1.96 at the flat rate, 9 of them red at the soft cap for $1.31. A read is 300 lines and a request, every request carries the conversation again and thinks before it answers, and reasoning was 80% of a capped run's cost; and twice a run has died on the argument the model keeps inventing for `read`. This version makes a read as large as the model asks for, gives it that argument, and makes a mistake in a call's shape cost a request instead of the run, so a cold run of this repository reads `builder.py` in two requests where it took six. And it makes the loop's own numbers a command, so the next version is opened on what the last one cost -- builds, red, capped, dollars, reviews and what they found -- and not on a tier written the day a seed was filed.

## Changelog

- A read is as large as the model asks for, and a mistake in a call's shape costs a request and never the run. `read(path, start, limit)`: `limit` is the most lines to return, omitted, zero or above the cap being the cap and a negative limit one; `READ_LINES_CAP` is 1000 and `READ_BYTES_CAP` 64,000, so `builder.py`, 1,579 lines and 78,941 bytes, is two reads where it was six and `test_builder.py` three where it was eight. A call with an argument a tool does not have, or without one it needs, is answered by the library's validation as `error:` answers every other mistake, and the run goes on: the tool retries sit above what a run can afford, and `SpendModel`, a wrapper that asks the spend before every request after the first, ends at `HARD_SPEND` a run whose calls never reach a tool -- which the first review found would otherwise run to `REQUEST_LIMIT` alone, twice the hard ceiling. The record gains `bytes_read` beside `lines_read`, a cut line counting the bytes returned, and `retries`, the library's corrections by the tool each named, `{}` for a run it never corrected; README names the argument, the caps and the two fields. Two runs, $0.23 at the flat rate: the first landed red at the cap on one test alone, the attended agent's byte-cap fixture left at 40,000 bytes, which the run's own unsure field named, so its tree was taken as the base and the fixture amended; the second green in 39 requests. Two reviews, eleven findings, every one reproduced with the reviewer's own probes, five of them tests and the rest judged with reasons. the-read-that-costs-a-request closed green with no build of its own, by the loop's ninth row; what the larger read saves is measured after this version ships, since a build runs on the installed product.
- What a version took is a command. `uv run gate.py numbers` prints one row per version, oldest first and the version in flight last: `seeds`; `runs`, the store's records by the seed each names, every run the version paid for whether or not git holds its tree; `builds`, git's commits by `Built-By` trailer; `green`, `red` and `capped` over the runs, a run landed by the soft cap capped though it answered; `unrecorded`, builds without a record; `cost_usd` and `requests`; `reviews`, the notes naming any of the version's runs or builds, with their `findings`, `defects` and judgements by kind, a finding once under each kind its line names; `commits` and `by_hand`. `tally.py` gathers one frozen `Tally` through `vault`, `repo`, `instance` and `runs` and nothing else, and every fact it cannot read is `None` with a line, as `next` prints them: a store the configuration does not name, a git that fails mid-gather, a note the vault cannot read or parse, two notes that are no tag. `repo.commits`, `runs.numbers`, `runs.records` and `runs.capped` are the readers it gained, `tool_errors` and `capped` sharing one walk of a record's returns. Five runs, $0.38 at the flat rate: the first, green in one run, answered the Goal as written, and the Goal was wrong -- it counted builds by trailer, so v0.21 read as 7 builds and $0.51 where its note had counted 14 runs and $1.52, and the reviews of its red runs matched nothing -- so the runs became the store's; the second rewrote the module and landed red at the cap, its tree taken as the base; three more fixed lines at 22 to 28 requests each. Four reviews, 21 findings, every one reproduced, eight of them tests. On this repository v0.21 reads 15 runs, 7 builds, 10 capped and $1.65; this version 7 runs, 5 builds, 2 capped, $0.61, 6 reviews and 32 findings. AGENTS.md sends the reader there for what a version took.
- The seed carries `reporter` and `kind`, and its Evidence opens with the commit it was read at. The template names both fields -- who saw it and through what, and what it moves -- the backlog shows them and groups by kind, and the 35 open seeds carry them from an audit of every open seed against the code as it stood, which moved nine labels and rejected one whose walk had gone at v0.20. Two seeds came out of the audit: the gate asking for the fields, and the rank at the moment a version opens as a command like `next`, since a commissioner never shares a backlog with the factory.
