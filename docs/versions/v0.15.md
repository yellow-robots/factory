# v0.15: the reviewer

The factory has had one role since v0.3: the builder, which writes code until the tests pass. Every diff it produced was read by the attended agent, outside the factory and unmeasured, and that reading is where the factory's quality has been won. This version gives the factory the second role. The reviewer runs a cold session, read only, over a tree a build left: it answers whether the code does what its tests claim rather than merely satisfying them, and what else changed, with findings it has reproduced and one verdict. Its run is recorded like the builder's, because a role that cannot be measured cannot be given a responsibility. It runs on a model of its own, stronger than the builder's, which the instance's configuration names along with the key it uses — and the wall that keeps a key out of a record now searches every record for every key the instance holds, not the one key the run was given.

## Changelog

- The instance's configuration describes the roles it runs: each names its model and the key file it reads, so neither is a constant of the program any longer, and a role a run asks for that the configuration does not hold is a usage error. The search that keeps a key out of a record searches every record for every key the configuration names, so a run made on one provider cannot commit a record carrying another's key.
