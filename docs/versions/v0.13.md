# v0.13: every build on the list

The gate refuses a release whose builds git cannot list: a build commit whose `Built-By` line git's own trailer parser does not read, or whose run is not a committed record, so the builds of a version are what `git log` derives and nobody has to look. `check` reads them too, so a build git cannot list is seen in the version's worktree, where the commit can still be amended, before main moves.

One seed, found by the attended agent reading the log on 2026-09-17. Built by the factory from the attended agent's tests, five builds under three independent reviews and one of the attended agent's, since the reading of one line of git's output has more edges than the seed's size suggested.

## Changelog

- `check` and `release` refuse builds git cannot list. The builds read are the commits reachable from HEAD and not from the highest tag, or every commit when there is none, listed and read as revisions with `--`, git asked for UTF-8 and no signature whatever the repository's display settings say, its output read as bytes so a carriage return stays one. A build is a commit with a line beginning `Built-By` in ASCII of any case, spaces allowed before the colon; what git reads are the entries of `%(trailers:key=Built-By,unfold,separator=%x00)`, and a build whose lines outnumber them is refused `as a trailer`. Every value, of a line and of an entry, must end `run <stamp>` with the stamp in the builder's own shape, or it `names no run`; every stamp must be a tree `runs/<stamp>` in HEAD's tree, once a commit. Problems name the commit by git's abbreviation whatever `core.abbrev` says, quote a value with its control characters escaped and nothing else changed, print once, and stand under the note of the version in flight or under `docs/versions/`; a git command that fails while the builds are listed or read is a problem naming it. Over this repository's history the check flags the four build commits of v0.7 and v0.8 whose `Built-By` git does not read, the four `AGENTS.md` names under what the repository does not derive, and nothing after v0.8.
- Five builds for the one seed, about 25 cents and sixteen minutes of model time, each green on the tests it was given. Three independent reviews, fresh sessions in this harness, and one by the attended agent: eight defects and nineteen smells, every one reproduced with the reviewer's own probes and judged in `docs/reviews/20260917T155212Z.md`, `20260917T162342Z.md`, `20260917T165741Z.md` and `20260917T173607Z.md`. The first review found only the first problem of a build printed and a failing git command reading as no builds at all; the second, a value git reads over two lines and a carriage return splitting a message, both of which let a release tag, and an empty value every commit seemed to hold; the third, a stamp in git's revision syntax passing as a record and a display setting hiding a build, both crafted and both fail-open. The Goal was rewritten whole after the second review, its two readings of a line having begun to disagree, and amended twice after that. One defect was the attended agent's: a test of an earlier round contradicted the amended Goal, the build kept both green by matching the stamp's shape at its start alone, and the last build closed it with `fullmatch`. What the reviews left unpinned is on file with the reason, chiefly inputs no commit of this workflow can make.
- The backlog took the eval framework's turn. From the owner's question on causality and a research task on eval practice, its every cited source read by the attended agent: five seeds opened, a run's world built outside this repository since the check mounts the whole checkout and code the model writes can read a pass word or a past run's fix, a check of the tree the model leaves, capability and integrity scored apart from what doing nothing scores, per-case intervals in place of one standard error, and harder cases taken from the reviews' own history; `notes-hidden-from-the-set` rejected with its reason, hiding not being removing; the labels seed and the paired-runs seed read again. The analyst seed holds the seven done seeds a replay can use and how git grades a spec, `tools-as-mcp` holds the first of its two claims checked, a headless session with one tool of ours and no other, and `the-vault-as-git-tracks-it` says a note git ignores is no note of the vault's.
