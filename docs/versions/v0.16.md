# v0.16: a budget the checkout earns, and a landing at the end of it

The caps were set at v0.3, when `builder.py` was three hundred lines and the suite thirty tests; the checkout the builder now works on is 13,044 lines the tools can reach across 142 files, and the caps have not moved. v0.15 spent seventy-eight per cent of its money on runs that were cut off, four of them with the check green and the whole change made, and nothing the spec could do reached them. This version makes the budget a function of what the run must read and gives the run a landing: the tools stop and say report now when the budget is spent, and the requests are derived from the calls so that a run always has the requests left to say what it did. The request cap has been below the tool-call cap since v0.3 -- sixty against eighty -- so the soft landing the tools already use for writes and checks could never fire for the run as a whole; the provider budget ran out first, every time.
