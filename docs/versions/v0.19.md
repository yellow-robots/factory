# v0.19: the number that decides the reviewer

v0.18 built a reviewer and said, in its own note and in `AGENTS.md`, that nobody should route a decision through it. That was not modesty. Its seed set the condition before a line of it was written -- a reviewer that catches nine of ten is a gate, one that catches four is theatre, and no amount of good prose in its report changes that -- and the number has never existed. This version is that number, and everything here exists to make it mean something.

Two things come before it. A role served somewhere else is still priced with DeepSeek's table, which overstates GLM by more than five times, so a GLM pass is landed after a fifth of the work it was given: asked today whether the stronger model is the better reviewer, the cases would compare a builder running to its budget against a reviewer cut off early, and answer confidently and wrongly. And the reviewer's own exit code cannot be trusted -- a review that did everything right returned 139 -- which is the one thing a harness reads to decide whether a case counted.

Then the harness. It runs the reviewer over `cases/`, twelve changes with seeded failures and held-out tests that know the right answer, and counts what it caught. What it prints is a rate and its error, because a single number with no error is what makes a four look like a nine. The first rate will be one model, one phrasing, one depth, over a corpus the factory wrote for itself, and the honest reading of it is narrow: it says whether this reviewer is worth routing a decision through, not whether reviewing works.

## Changelog

- A run is priced by what it ran on, or it does not run. `PRICE` was the fallback for every model, so a role served elsewhere was priced at DeepSeek's rate: GLM was overstated 5.41 times, and since v0.17 made spend the thing that bounds a run, a GLM pass was landed after a fifth of the work it was given with the record reading the ceiling either way. The library now prices what it can, **asked at the address the role is reached at** -- `glm-5.3-flash` is served by two vendors at rates 29% apart and the bare name resolves to the wrong one -- and `cost_source` names the source that answered rather than the name that was configured. The library's own running total is no longer used: it adds a response's cost only when it was given one and its tokens always, so a partially priced run recorded the price of the part, measured 74 times too loose. A role neither source can price is refused before a model is called and before a record is made, exit 2, naming the role and the model, because a ceiling derived from another model's rate is not a ceiling. `deepseek-flash` costs exactly what it always cost, by the same table, so every record ever written stays comparable.
