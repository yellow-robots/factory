# v0.12: the error bar that never lies flat, and a test the model never sees

The set's standard error is the one of the rate it prints, under a uniform prior, so a perfect score with three runs is not read as certain and one run still carries an error. A case may hold tests the model never sees, run after the build in the same container, so the set measures whether the builder built the thing and not only the tested thing; the first such cases are a docstring left behind and a symptom fixed instead of its root.

Four seeds, from the owner's question on attempts and the eval framework of 2026-09-17, and one found by this version's first build, which said in its unsure list that an edit had reported success and changed nothing: the library ran a response's tool calls overlapping, two edits of one file raced, and the tools now run one at a time. Built by the factory from the attended agent's tests; the cases are the attended agent's, like the tests.
