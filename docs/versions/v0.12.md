# v0.12: the error bar that never lies flat, and a test the model never sees

The set's standard error is the one of the rate it prints, under a uniform prior, so a perfect score with three runs is not read as certain and one run still carries an error. A case may hold tests the model never sees, run after the build in the same container, so the set measures whether the builder built the thing and not only the tested thing; the first such cases are a docstring left behind and a symptom fixed instead of its root.

Four seeds, from the owner's question on attempts and the eval framework of 2026-09-17, and one found by this version's first build, which said in its unsure list that an edit had reported success and changed nothing: the library ran a response's tool calls overlapping, two edits of one file raced, and the tools now run one at a time. Built by the factory from the attended agent's tests; the cases are the attended agent's, like the tests.

## Changelog

- The line after the table prints the standard error of the rate it prints: each case's variance under a uniform prior, (k+1)(n-k+1) over (n+2)^2 (n+3), summed over the cases, rooted and divided by the case count, never zero and defined at one run, in place of the round's spread with the n/(n-1) correction that v0.11 printed under that name. Over the two set runs on file it gives v0.6 0.778 with 0.057 and v0.7 0.963 with 0.056; the difference is 2.3 standard errors of the difference, so the v0.7 rise is shown, where v0.11's note read it as not shown from the wrong number. Attempts stay at three by default, ten on a case that varies or on a full set when a version changes what the model sees. The six tools run one at a time in the order the model gave them, `sequential` in the library: the version's first build said in its unsure list that an edit had reported success and changed nothing, and the record showed three edits in one response, the first lost to the third's write; a test with a slow edit reproduces the loss and pins the order. A case may hold `held_out/`, tests the model never sees: after a green build they are copied into the worktree and the check runs once more through the sandbox, its log and exit code in the record, a `held_out` column right after `green`, and a green case passes only when both checks did. Two cases carry them: `docstring_left_behind`, a behaviour change whose two docstrings must follow, and `symptom_not_root`, a debit that does not lower a balance because the line parser drops its sign, the visible test on the sum and the held-out one on the parser; both staged by hand as red as shipped, green on the visible test alone under the half fix, green on both under the whole one.
- Four builds for three seeds, about eleven cents and seven minutes of model time, all green; the fourth seed, the two cases, is the attended agent's and needed none. One independent review of the first three builds, a fresh session in this harness, accepted them with three defects and nine smells, all reproduced by the attended agent and on file in `docs/reviews/20260917T103739Z.md`: a nested or absent held-out test counted as a pass, the held-out copy replacing the case's test or the builder's work, and a raising held-out check throwing the green build's record out of the table, all three tests and one follow-up on the amended Goal, which also reads the fact that a case holds held-out tests once and refuses a bool as an exit; the docstring's enumeration of the counts stale behind a test that pinned the old phrase, the test widened and one more instance for the stale-docstring-case seed; a red case paying for a held-out check nobody reads, a test; the rest none with the reason, among them that `seconds` in a record before v0.12 is not comparable with after, since a response's calls now take the sum of their durations instead of the longest, and that the held-out check's number reaches nothing but a container's name. The main guard of `test_evals.py` sat above the version's tests for the second version running, the attended agent's fault, and the red scripts insert above it now. The set at the version's head, eleven cases three times each, 33 of 33 passed, pass rate 1.000 with standard error 0.049, 33 cents and 34 minutes: both held-out cases green on both checks in every run, the docstrings followed and the parser's sign restored at its root, and the tempted test refused three of three where v0.7 had two. The 33 records are in `runs/`, the first set run since v0.7.
