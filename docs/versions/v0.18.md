# v0.18: the reviewer, and the bound that is no longer there

v0.17 made what a run has spent the thing that bounds it, and left the walk that used to do the job still running beside it, deriving a number nothing reads. That goes first, because a program with two bounds where one is dead is a program that lies to whoever reads it next, and because it is the one goal of that version that did not land.

Then the role this factory has been running by hand since v0.2. Every diff so far was read by a model in another harness, prompted by a human each time, its findings typed into a note by the attended agent, and no record of any of it kept. That work has found real defects in every version it has touched -- two of v0.17's, including one the version itself created, and both times what the code did was what the tests asked and not what the Goal did. A suite cannot catch that, because the suite is the thing being satisfied. The reviewer is the second program of the factory's: a cold session over a delivered tree, read only, recorded in the store like any other run, because a role that cannot be measured cannot be given a responsibility.

It ships against a number and not against an opinion. `cases/` is a set of changes with seeded defects and held-out tests that know the answer, and the catch rate against them is what this role is worth. Nine of ten is a gate; four is theatre, and no amount of good prose in a report changes that.

## Changelog

- `reviewer.py`, a second program of the factory's and the first it has written from nothing: a cold session over a delivered tree that reads and cannot write. The model is offered `list`, `read` and `search` and the tool its report returns through, and never `write`, `edit` or `check` -- not refused at a wall, never offered, because a model told it has a hand it does not have spends calls discovering otherwise. It builds no container and runs nothing of the project's. The confinement, the wire, the record, the key scan the store insists on and the caps are the builder's, reused rather than rewritten.
- A review is five independent passes and what is made of them. No pass is told what another found. What two or more passes reached is reported and what one reached alone stays in the record, while the numbers count everything seen. Two passes found the same thing when they name the same path and the same line -- never the prose, which would need a second model's judgement. Every reported finding carries how many passes reached it, and the answer says how far they agreed and never that a contract is met, because five passes cannot warrant that.
- A role says where its model is served. `base_url` has been read from the configuration since v0.15 and used by nothing, so the reviewer role this host configures -- `glm-5.3-flash`, with its own key -- would have sent that key to DeepSeek in an `Authorization` header for a model DeepSeek does not serve, with the wire redacting the header so the record would not show it. Both programs now reach a role where it says it is served, and DeepSeek's answer to its own forced-tool-choice hazard is no longer claimed of models that are not DeepSeek's.
- The reviewer's second argument is a seed, always. `read_seed` takes a non-`.md` argument as the goal text itself, which is right for the builder and wrong here, so one forgotten `.md` walked past every refusal and spent a full priced session reviewing a real diff against a one-line pseudo-goal, committing it with `seed` null and exiting 0.
- The first review of `reviewer.py` is in `docs/reviews/`. Eight findings, two defects, both built the same night. Four smells became six guards, each confirmed to kill a one-line mutant that had passed the whole 262-test suite -- including deleting the key scan outright, and narrowing it to this run's own key, which is the regression `keys-of-the-instance` exists to prevent. Two more are judged `none` and marked unreproduced rather than dressed up, and carried by `what-a-review-does-not-say`.
