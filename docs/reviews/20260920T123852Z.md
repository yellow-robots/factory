One review of the four builds that made `catch.py`, read as one change. The brief asked for the scoring arithmetic and the error bar to be checked against `evals.py` and against a hand calculation, and for a mutation pass over the new tests, because this is the program that produces the number every future judgement about the reviewer will rest on.

**What it confirmed sound**, which matters as much as what it found: `_rate` is bit-identical to `evals.py`'s own `_pass_rate` over every input tried, the variance is the Beta(k+1, n-k+1) posterior, and the live `0.500 ± 0.224` for one catch of two is exactly that by hand. The spend guard has no off-by-one and no float trouble; `nan`, `inf`, `1e400`, negatives and garbage are all usage errors. The worktree is removed even when the review raises, and its root is a per-run `mkdtemp` that cannot clobber. So the rate this harness printed is the rate, and the defects below are in what is fed to the arithmetic and in what holds it.

## Findings

### Scoring when nothing at all was measured is a crash

severity: defect
verified: yes
judged: test test_scoring_when_nothing_was_measured_is_an_answer_and_not_a_crash

`_score` stopped appending unmeasured cases and still called `_rate` whenever any case was selected, so the rate divides by zero. Reproduced on the live checkout: `catch.py --score the-work-a-capped-run-leaves` ends in `ZeroDivisionError`, exit 1, having printed nothing useful.

**This was mine, in the fix of an hour before**, and the test I wrote for that fix always had one measured case, so it never reached the empty path. It is the ordinary order of work -- write a case's answers, score, then decide whether to spend on it -- and it failed at the first step.

### A review that could not be started counts as a case the reviewer missed

severity: defect
verified: yes
judged: test test_a_review_that_could_not_be_started_is_unmeasured_too

The same defect on the running path, where the money is. A commit git cannot check out, a reviewer that refused, anything that raised: all return a full miss and go into the rate. Reproduced offline with a case naming a commit that does not exist: the row reads `bad 0 0` and the printed rate is 0.500 where the one case actually measured scored 1.000. The exit is 1, but the rate is the number people quote.

### The error beside the rate is held by nothing

severity: smell
verified: yes
judged: test test_the_error_beside_a_rate_is_the_error_of_that_rate

Three separate mutations of the standard error survived all 312 tests: zeroing it, leaving it undivided, and dropping the numerator of the variance. The only assertion on it checked that a `±` appeared somewhere in the last three lines. The seed's own words are that *a single number with no error is the thing that makes a four look like a nine*, so of everything in this program this was the worst thing to leave unpinned.

### The rate's denominator is held by nothing

severity: smell
verified: yes
judged: test test_the_rate_is_counted_over_what_the_case_knows

Counting catches over catches rather than over what the case knows survived: the mutant prints `1.000` for any case that caught anything at all. The `known` column of the row was pinned; the denominator the rate divides by was not.

### A span's ends and its lower bound are held by nothing

severity: smell
verified: yes
judged: test test_a_span_holds_its_own_ends_and_nothing_before_them

Dropping the lower bound survived, and so did making both ends exclusive. The corpus turns on exactly this: the answer span `[186, 191]` was narrowed after the first run so that 191 is inside and 192 is outside, and without a lower bound a finding anywhere earlier in the file would have scored.

### One answer can be caught many times on the path count

severity: smell
verified: yes
judged: test test_one_known_finding_is_caught_once_however_many_name_its_file

The de-duplication is on the answer's side and a mutant counting every report that named the file survived. On the first real record fourteen of sixteen findings name `reviewer.py`, so that mutant would have printed a path rate of fourteen against two known.

### Nothing could tell whether the harness reviews the case's commit or the head

severity: smell
verified: yes
judged: test test_a_case_is_reviewed_at_the_commit_it_names_and_not_at_the_head

The whole measurement rests on checking out the case's commit, and replacing it with `HEAD` passed every test -- because the fixture made that commit the head. Real cases name commits with descendants, `3e01d73` and `8125f19`. The production code was correct; only the test was blind, which is the same blindness as the answer-span collision of the first run and in the same place: a fixture that cannot tell two things apart.

### A case that knows no findings averages a zero into the rate

severity: smell
verified: yes
judged: test test_a_case_that_knows_no_findings_is_not_a_case

A `.toml` with a commit and a seed and no finding table scores zero of zero and is averaged in, so adding an empty case halves the number. It is the same arithmetic as the unmeasured-counted-as-a-miss defect this seed has now met three times.

### The printed ceiling is about twice what a review can spend

severity: smell
verified: yes
judged: seed the-ceiling-that-is-not-the-ceiling

The guard refuses when `cases x dimensions x passes x HARD_SPEND` exceeds the allowance, $5.00 a case. But the reviewer stops *starting* passes once it has spent `dimensions x passes x SOFT_SPEND`, so a review's true maximum is about $2.50 plus one pass's $0.25. The guard errs safe and will refuse affordable runs: the twelve-case set would demand $60.00 where it cannot exceed about $33. The seed derived $5.00 too, so the spec shares the overstatement -- and the number matters, because it is the number the owner is being asked to decide about.

### Path matching is exact string equality

severity: smell
verified: yes
judged: seed the-ceiling-that-is-not-the-ceiling

`./reviewer.py`, an absolute path, or a stray space all score zero against `reviewer.py`, and `reviewer.py`'s prompt only asks for the path *as the checkout names it*. The real DeepSeek run returned clean relative paths so it has never bitten, and a model that prefixed `./` would score 0.000 with nothing looking wrong.

### A record whose numbers cannot be read has them overwritten

severity: smell
verified: no
judged: seed the-ceiling-that-is-not-the-ceiling

`_numbers` returns `{}` on any parse failure and `_tag` then writes `{"goal": ...}` over `numbers.json` and commits it. The harness's recovery from *I cannot read this record's numbers* is to replace them. It needs an already-damaged record, so the attended agent did not reproduce it; the review did, on a record with deliberately invalid JSON.

### `--score` will take a record that is not a review

severity: smell
verified: no
judged: none: no collision exists and the two sets' names are the attended agent's to keep apart

`_case_of` checks only that a goal begins `case: `, which `evals.py` uses for the builder's cases too, so a name shared between `catches/<n>.toml` and `cases/<n>/` would silently score a build record. No such name exists and both sets are written by hand.

### A case name is not confined to `catches/`

severity: smell
verified: no
judged: none: the set is driven by hand and nothing reads a name from anywhere else

`catch.py --score ../elsewhere` and an absolute path both load that file. Worth a name check the day anything but a person supplies the name.

### Overlapping answers within one case are both matched by one finding

severity: smell
verified: yes
judged: none: corpus hygiene, and the same shape as the span collision the first run already taught

Two answers whose spans overlap are both strict-matched by a single report inside both. Nothing warns. The answer is to not write overlapping spans, which is what the first run's correction already made the habit.
