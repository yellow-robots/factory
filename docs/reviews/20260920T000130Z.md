## Findings

### The reviewer role's key is POSTed to the provider the role did not name

severity: defect
verified: yes
judged: seed the-role-served-somewhere-else

`reviewer.py` takes `role.model` and `role.key` from the configuration and never reads `role.base_url`; `build_agent` hardwires `DeepSeekProvider`, so the endpoint is DeepSeek's whatever the role says. `instance.py` has read the field since v0.15 and nothing has ever used it.

The attended agent had found the same gap independently, minutes earlier, and filed the seed. The review is sharper about what it costs, and the sharper reading is the right one: this is not a role that fails to work, it is **another vendor's key leaving the host in an `Authorization` header to DeepSeek**, for a model DeepSeek does not serve. The wire redacts that header in the record, so the record would not show it.

It is live rather than latent, which the attended agent confirmed by reading `test_instance.py`: the helper named *the configuration this host runs* carries `[roles.reviewer]` on `glm-5.3-flash` with `base_url = "https://example.invalid/v1"`, and `keys-of-the-instance` records that the owner placed `glm.key` on the host for the reviewer to use. Built the same night, in run 20260920T002706Z.

### A seed path with the `.md` forgotten is not refused; it becomes the goal

severity: defect
verified: yes
judged: test test_an_argument_that_is_not_a_seed_path_is_refused_and_costs_nothing

`builder.read_seed` reads `docs/seeds/<name>.md` as a seed and anything else as the goal text itself, which is right for the builder, whose second argument is documented as text or a seed, and wrong for the reviewer, which prints `usage: reviewer.py <checkout> <seed>` and records a `seed` field.

Reproduced by the attended agent as a test: `reviewer.py <checkout> docs/seeds/a-seed` exits 0 where it must exit 2. It spends a full priced model session reviewing a real diff against the one-line pseudo-goal `docs/seeds/a-seed` and commits the record with `seed` null. A directory and arbitrary prose do the same. Every `.md` path already refuses correctly -- absent, uncommitted, a symlink, no `## Goal`. The Goal was amended to the correction and the fix built the same night.

### The key scan can be deleted and the whole suite stays green

severity: smell
verified: yes
judged: test test_the_record_reaches_the_store_and_not_only_the_disk, test test_the_record_is_searched_for_every_key_the_configuration_names

The code is right and nothing held it there. Replacing `builder.commit_record(store, run_dir)` with `pass` -- which removes the key scan and the commit together -- passed all 262 tests, because the tests assert the record's files exist in a directory and a directory is not a commit. Narrowing the scan to this run's own key with one keyword, `key=key`, also passed: that is precisely the regression `keys-of-the-instance` exists to prevent, whose own words are that the wall does not fail loudly, it passes.

Both reproduced by the attended agent against the current tree and both now killed, confirmed each way. The second guard plants the *builder's* key value in the change under review, which this run never reads and must still refuse.

### The role text can tell the model it can write, edit and check

severity: smell
verified: yes
judged: test test_the_role_does_not_tell_the_model_it_can_change_anything

`ROLE = builder.ROLE` passed all 262 tests. The builder's role says to change the checkout with `write` and `edit` and test it with `check`, and the Goal's whole stated reason for never offering those three is that a model told it has a hand it does not have spends calls discovering otherwise. The only test that read `ROLE` scanned it for four words about confidence. Reproduced and killed; the guard checks the tool names backticked, since `check` also occurs inside `checkout`.

### The tools can be rooted anywhere, including outside the checkout

severity: smell
verified: yes
judged: test test_the_tools_are_rooted_at_the_checkout_and_nowhere_else

Rooting them at `/etc` passed the whole suite, because no test ever called `list`, `read` or `search` through the reviewer -- every test's model answered on its first response. The walls are `builder.Tools`' and are tested there; what was untested is that this program hands them the right root. Reproduced and killed.

### The change can be shown to the model backwards, and a run that never reported can exit 0

severity: smell
verified: yes
judged: test test_the_change_is_shown_in_the_direction_it_was_made, test test_a_run_that_did_not_report_says_so_in_its_exit

Swapping the two ends of the diff passed, because the assertion looked for `x = 2` and a reversed diff still contains it as a removal. And `return 0 if stopped == "answer" else 1` could be `return 0` with nothing noticing, since no test had ever reached a cap. Both reproduced and both now pinned.

### A dirty checkout is neither refused nor recorded

severity: smell
verified: no
judged: none: the Goal does not ask for the refusal, and the reviewer's own harness will hold the tree clean; it is written into `what-a-review-does-not-say` for when it is run by hand

`builder.main` refuses a checkout with uncommitted or untracked changes so a build is reproducible; `reviewer.py` does not. The tools serve the working tree while the diff in the prompt is `parent..head`, committed, so they can disagree silently and the record says nothing about it. Not reproduced by the attended agent for want of the night, and recorded as the reviewer reported it.

### `WireModel` keys on the test seam rather than on whether the model speaks HTTP

severity: smell
verified: no
judged: none: recorded in `what-a-review-does-not-say`; production is clean today and the seam matters for goal D's harness rather than for goal A

`run_model = None if model is None else WireModel(model, wire)` decides "does it go over HTTP?" by "did a caller pass a model?", and `build_agent` discards `http_client` whenever `model` is given. Hand `main()` a real model and the record keeps a request line with an empty url and no response at all. The attended agent verified separately that production is unwrapped and the real wire records the genuine request, so the test's assertion still means something; the seam is what `evals.py` and `build.py` both use, which is why it is written down rather than dismissed.

## Where nothing was found

The confinement holds, which is the thing that would have been worst to get wrong. A model that tries `write`, `edit` and `check` gets `Unknown tool name` for each; the agent's own tool lists are the three that read plus the output tool; nothing in `reviewer.py` builds a sandbox, invokes docker or runs a subprocess of the project's; `Tools` is built with no sandbox and the final check is never called, so no container exists and no check log appears in the record; and the only writes are into the run directory and the store's git.

The record reaches the store as one commit, key-scanned first. A key planted in the change under review travels through the prompt into `messages.json`, and the store refuses the record: exit 1, the file named on stderr, the value never printed, and nothing committed.

The usage errors are real refusals apart from the finding above. Nineteen probes -- a plain directory, a subdirectory, a nonexistent path, a head with no parent, a commit-less repository, a seed absent, uncommitted, symlinked or without a `## Goal`, `records` a plain file, `records` inside the checkout, no `reviewer` role, an empty key file, a missing key file, a missing configuration, `FACTORY_INSTANCE` set empty, and the wrong argument count -- each exit 2, each in its own words, with no model called and no record made, and none of them raised.
