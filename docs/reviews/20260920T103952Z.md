One review of both builds of [[the-role-priced-as-another]], read as one change, `50fdc63..6d59e7c`. The brief asked for the paths from a configured model name to the two numbers that matter, and for a mutation pass over the new tests. Eleven of thirteen mutants died; the two that lived are the first and fourth findings here.

## Findings

### The number the tools land a run on is held by no test

severity: defect
verified: yes
judged: test test_the_tools_land_a_run_on_the_price_of_its_own_model

Putting the table back into `main`'s `spent` -- this seed's own defect, on the path this seed says matters -- leaves all 293 tests green. Reproduced by the attended agent on a copy of the checkout: one `sed`, one suite run, `Ran 293 tests OK`.

The code was right and nothing held it. Every test written for this seed asserted the record's `cost_usd`; none asserted what the tools answer, which is the number that decides when a run is landed. The Goal's own closing sentence -- that the two are the same arithmetic and cannot drift -- was true of the code by inspection and by nothing else.

The test is the review's own shape: 500,000 uncached input tokens cost $0.15 by the table and $0.0375 at the rate of the address the role is served at, so a tool that refuses is a tool bounded by a rate that is not its model's.

### A role is priced by a provider the library guessed, not the one it is served by

severity: defect
verified: yes
judged: test test_a_role_is_priced_by_the_row_for_the_address_it_is_served_at

`price` is handed the model's name alone, so `genai_prices` scans providers and answers with whichever it finds first. `glm-5.3-flash` is served by two of them at different rates, and the bare name resolves to the one this host does not use.

Measured by the attended agent on the tokens of run 20260920T103528Z:

| asked as | provider | cost |
|---|---|---|
| the bare name | `zhipuai` | $0.000196624 |
| `provider_api_url=https://open.bigmodel.cn/api/paas/v4` | `zhipuai` | $0.000196624 |
| `provider_api_url=https://api.z.ai/api/paas/v4` | `zai` | $0.000253495 |

The owner's configuration names `https://api.z.ai/api/paas/v4`. **So the reviewer role is priced 29% low today**, by the build that exists to stop exactly that: the seed removed a 5.41x overstatement and shipped a 1.29x understatement on the same model, in the same direction of harm reversed -- a pass now runs past its budget rather than short of it. The Goal already said what was needed in as many words, *a provider and a model it can look up together*; only the model half was passed.

The review's second half of this finding, that 1,211 model ids price only when the provider is named and are now falsely refused, **did not reproduce as stated**: its example, `deepseek-v4-pro` at `https://api.avian.io/v1`, raises `LookupError` when asked with that address and prices fine by bare name -- the opposite way round. The Goal's amendment therefore asks for the address first and the bare name when there is no address or the library does not know the one there is, which is correct in both directions.

### A run the library priced only in part is recorded at the price of the part

severity: defect
verified: yes
judged: test test_a_run_the_library_priced_only_in_part_is_priced_by_the_one_function

`RunUsage` adds a response's cost only when the library gave one for that response, and adds its tokens always. A partial sum is not `None`, so the fallback to the one function never fires and the sum of some responses becomes the whole run's price.

Reproduced by the attended agent directly on `RunUsage`: a priced response of $0.001, then one of 1,000,000 input and 100,000 output tokens the library could not price, gives `usage.cost` $0.001 against `price()`'s $0.07437 on the same tokens. **The run is bounded about seventy-four times too loosely.**

It was dormant before this change -- `deepseek-flash` has no row, so `usage.cost` was always `None` and the fallback always fired. Putting roles on models the library prices is what made it live, which is the shape of the whole seed: the fix to one model's price is what exposes the next.

### `cost_source` is read off the model's name rather than off the source that answered

severity: defect
verified: yes
judged: test test_a_review_s_record_names_the_arithmetic_that_priced_it

`"table" if model_name == MODEL else "genai-prices"`, in both programs. That is a regression: the code before this seed derived it from `usage.cost is not None`, which was always true of the arithmetic that ran.

It is not reachable on the pinned data, because the library has no `deepseek-flash` row. It becomes reachable on any dependency bump that adds one, and what it would hide is precisely the clause the Goal ends on -- our own model must keep costing what it costs today. A record priced by the library would still read `table`.

The reviewer's copy of the line was held by nothing at all: inverting it survived the whole suite. That is the second mutant that lived.

### The check that a model can be priced swallowed `TypeError` and admitted everything

severity: defect
verified: yes
judged: test test_a_run_is_not_admitted_because_the_price_could_not_be_asked

`require_price` catches `TypeError` and returns quietly, so anything making the asking itself fail admits every unpriceable model. The review reproduced the full consequence: refusal gone, model called, a half-made record left in the store.

**The cause is mine and it is the third instance of one lesson in one seed.** When this seed gave `price` a model, two stand-ins at `test_reviewer.py:537` and `:551` kept the old one-argument shape -- `mock.patch.object(reviewer.builder, "price", lambda usage: 0.10)`. I grepped for `builder.price(` and amended the call sites; a `mock.patch.object` naming the function as a string is a call site that does not look like one. `test*.py` is PROTECTED, so the builder could not repair the doubles and defended itself in production code instead, and its `unsure` said so. Both doubles now take a model, and the branch has no caller left.

The same seed taught the same lesson twice before: the first build could not reach two of its clauses because fixtures named unpriceable models, and goal C's first build was red because four dimensions were added while tests asserting five were left standing.

### `price` catches only `LookupError`, and the library also raises `ValueError`

severity: smell
verified: yes
judged: seed the-price-the-library-would-not-give

`calc_price` raises `ValueError` on a usage it will not accept, such as more cache reads than input tokens. `price` catches `LookupError` alone, so a `ValueError` escapes through `spent()` -- which the tools call unguarded on every call -- and through the record's own pricing, losing the record. pydantic-ai's own helper catches both.

Verified as an escape, not as a reachable one: neither the review nor I found a path to it from DeepSeek or Zhipu, and it needs a provider reporting impossible token counts. It is a provider's bug becoming our lost record, which is worth fixing and is not worth widening this build for.

### The suite now turns on a third-party price row

severity: smell
verified: yes
judged: none: the dependency is the point, and it is pinned

The reviewer fixture and three key tests run on `glm-5.3-flash` and assert against the library's row for it, so a `genai-prices` bump that drops, renames or reprices that row turns a slice of the suite red. That is commit 5819aff, mine, and it was a deliberate trade: the names those fixtures used before were unpriceable, which is what made this seed's refusal unreachable.

Left as it is, because the row for the model we actually run is a thing we want to be told about. `uv.lock` pins it, so it moves only when someone moves it, and the suite going red is how they find out.

### `genai_prices` is imported at module scope and declared nowhere
