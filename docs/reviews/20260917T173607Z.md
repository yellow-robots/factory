### The stamp's shape is matched at its start, so revision syntax after a good stamp passes

severity: defect
verified: yes
judged: test test_release_refuses_a_build_that_names_no_run, test test_the_builds_are_read_as_git_reads_trailers

`STAMP_SHAPE.match` reads eight digits, `T`, six digits and `Z` at the start of the stamp and nothing after, so `20260917T000000Zx-g<hex>^{tree}` has the shape, git reads `HEAD:runs/<stamp>` as describe output peeled to a tree, and a release with no `runs/` at all exits 0 and tags. Reproduced with the attended agent's probe. The cause is the attended agent's: the Goal amended for the fourth build says a stamp has the builder's shape, and the test of the round before still looked a stamp followed by a no-break space up as a record; the builder kept both green by matching the start and said so in its report. The test is corrected to the Goal, a stamp followed by a no-break space names no run, and a stamp of the builder's shape followed by revision syntax is refused as naming no run.
