## Findings

### The wheel's path is read from the stream uv does not write it to

severity: defect
verified: yes
judged: test test_release_builds_the_product_at_the_clean_tag_and_says_where_it_is

`_build_wheel` (gate.py:1065-1085 at 1bb4c55) scans `done.stdout` for a line whose last word ends in `.whl`. Reproduced twice on 2026-09-21. By the attended agent in the version's worktree: `uv build --wheel >out 2>err` on uv 0.8.0 exits 0 with `out` empty and `err` holding `Building wheel...` and `Successfully built dist/factory-0.20.dev9+g7314e28d4.d20260921-py3-none-any.whl` -- the announcement is on stderr and the path is relative to the root, absolute only when `-o` names an absolute directory. By the reviewer, end to end: a `git init` repository holding the tree's `pyproject.toml` and five modules, one commit tagged `v0.2`, and `gate.main(["gate.py", "release", "v0.2"])` with the real uv on PATH exits 1 printing `docs/versions/v0.2.md: uv build --wheel failed: uv build named no wheel`, the tag standing, `CHANGELOG.md` absent and the wheel present in `dist/`. A second `release v0.2` is then refused as already tagged (gate.py:1015-1016), so the changelog and the path are recovered by hand. The builder's own unsure field said the real output had never been exercised; the tests' shim printed the line bare on stdout, which was the attended agent's error and not the builder's. Judged to the test: the shim now writes what uv writes, on stderr, relative, with the escapes below, and an older wheel is left in `dist/` so the path printed must be the wheel this release built; the Goal now says the path is found in `dist/` and not read off what uv prints.

### Colour in uv's output defeats the parse on either stream

severity: defect
verified: yes
judged: test test_release_builds_the_product_at_the_clean_tag_and_says_where_it_is

uv honours `FORCE_COLOR` and `UV_COLOR=always` when its output is a pipe or a file, and `_build_wheel` passes the caller's environment through (gate.py:1070-1076). Reproduced by both readers with `FORCE_COLOR` set, as it is in the attended agent's session: the captured line is `Successfully built <ESC>[36m<ESC>[1mdist/factory-0.2-py3-none-any.whl<ESC>[0m<ESC>[39m`, its last word ends in `[39m` and not `.whl`, and the parse yields nothing even once it reads the right stream. Same test: the shim's line carries the escapes.

verified: yes
judged: none: README.md is the attended agent's page and was rewritten in 7314e28, after the commit reviewed, to install the wheel with `uv tool install`; AGENTS.md's step 6 and its instance trap follow at release, when the gate requires it changed

At 1bb4c55 README.md:140-145 still installs an instance by `git clone --branch <tag>` and `uv sync`, and `[tool.uv] package = false` means that install never holds the product: `python -c "import build; print(build.version())"` in such a checkout prints `unknown`, reproduced by the reviewer, so an instance moved as README described would sign every build `Built-By: factory at unknown`, and README.md:156-158, "names the tag the instance stood at", would be false.
