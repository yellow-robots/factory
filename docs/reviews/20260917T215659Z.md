## Findings

### A stamp of digits outside ASCII passes as a run, and the release tags

severity: defect
verified: yes
judged: test test_release_refuses_a_build_that_names_no_run

`STAMP_SHAPE` is `\d{8}T\d{6}Z` with no `re.ASCII`, so `\d` matches any Unicode decimal digit and a stamp written in Arabic-Indic digits has the builder's shape. Until this build the lookup of `runs/<stamp>` in HEAD's tree refused it; with the lookup gone the shape is all that is read, and the reviewer released a version green on such a trailer where the parent commit refused it. Reproduced by the attended agent: `gate.STAMP_SHAPE.fullmatch` on those digits is true and false under `re.ASCII`. The rest of the module is deliberate about this, `BUILT_BY` compiled with `re.ASCII` and `_ascii_words` beside it, so the stamp's pattern was the one left. The Goal asked for the whole stamp in the builder's shape and the builder writes ASCII digits alone.

### A guard and a set in `_commit_build_problems` that nothing can reach

severity: smell
verified: yes
judged: seed records-outside-the-project

With the lookup gone, `_segment(stamp)` cannot fire: every string that `STAMP_SHAPE.fullmatch` accepts is non-empty, is not `.` or `..` and holds no slash. The `seen` set and its `add` beside it cannot see two different problems for one fault either, since the only problem left inside the loop names the commit and the value. Reproduced by the reviewer by deleting each and running the gate's tests green. The same `_segment` call in `_review_runs_problems` stays: a review's stamp is still read as a name. The Goal of the seed now asks for both to go; no test pins their absence, and the build that was given it left them, which the commit says.

### `release` can still print a problem that begins `runs/`

severity: smell
verified: yes
judged: none: the rule is the dirty tree's, which the Goal did not touch; a record no longer lands in the project's tree, and the one that did, the builder's own, is gone with the store

The Goal asked that no problem of `check` or of `release` begin `runs/`, and one can: the dirty-tree rule of `_release_problems` prints `<path>: uncommitted change` for anything git reports, `runs/` among them. Reproduced by the reviewer with an untracked `runs/` in the checkout. It is the generic rule and exempting a path from it would be worse. What made it likely was the builder writing its record beside itself, inside this repository; the store's half of the seed moved the record out, and the 146 records left the tree in the same version, so an untracked `runs/` is now a directory nobody writes.
