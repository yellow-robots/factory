## Findings

### A stamp in git's revision syntax passes as a committed record

severity: defect
verified: yes
judged: test test_release_refuses_a_build_that_names_no_run_or_a_run_not_committed

`git cat-file -t HEAD:runs/<stamp>` reads the whole argument as a revision first, so a stamp ending `-g<hex>^{tree}` named the tree of a commit and passed with no `runs/` at all, and a committed record named `run-g<hex>` was refused. Reproduced with the reviewer's probe: check exit 0, release exit 0, tagged. No stamp the builder makes has that shape, since every record is named eight digits, `T`, six digits and `Z`. The Goal is amended before the fourth build: the stamp must have that shape, which also keeps control characters out of the `runs/<stamp>:` path a problem starts with.

### `release` reads the builds a second time

severity: defect
verified: yes
judged: test test_release_reads_only_the_builds_since_the_previous_tag

The Goal says `release` runs `check` first and does not read the builds again; the third build kept the call in `_release_problems` and said so in its report. Reproduced: the listing ran from `problems_check` and from `_release_problems`, and a failure of the second alone refused a release whose check had passed. The test now counts the `git rev-list` a release runs.

### A failing abbreviation is swallowed, and a failing record lookup reads as a missing record

severity: smell
verified: yes
judged: none: `rev-parse --short=7` on a full hash reads no object and fails only when git cannot run, when the listing has already failed, so the Goal is amended before the fourth build to name the commit by its first seven characters when git cannot abbreviate it; `cat-file`'s exit status does not tell a failing lookup from an absent record, and both refuse.

Injected in the process: with `rev-parse` failing, check was silent on a good build, the fallback naming the commit; with `cat-file` failing, the problem said the record was missing. Reproduced with the reviewer's probe.

### The reads follow the repository's display settings

severity: smell
verified: yes
judged: test test_a_message_git_prints_in_another_encoding_does_not_end_the_release

With `i18n.logOutputEncoding` at UTF-16, git printed `%B` in UTF-16, no line matched, and a build git does not read, its run unrecorded, was released and tagged; with `log.showSignature` on, a signature was counted as an entry and the problem named a key fingerprint for a run. Reproduced. The Goal is amended: git is asked for UTF-8 and for no signature whatever the repository's settings say.

### The reads of each commit do not end their revisions with `--`

severity: smell
verified: yes
judged: test test_a_git_failure_refuses_the_release_and_no_path_hides_the_builds

A file at the root named like the full hash of a commit in the range made `git log -1 … <hash>` ambiguous, and check reported the read as failed instead of the build's problems. Reproduced. The Goal is amended: the commits are listed and read with their revisions ended by `--`.

### A stamp is printed raw in the path a problem starts with

severity: smell
verified: yes
judged: test test_release_refuses_a_build_that_names_no_run_or_a_run_not_committed

A stamp holding an escape sequence and separators split a problem across lines and wrote a terminal control code. Reproduced. The stamp's shape, amended above, admits digits, `T` and `Z` alone.

### A failing `git tag -l` reads as no tag

severity: smell
verified: yes
judged: none: `_tags` has read the tags for the whole gate since v0.4, and a configuration that makes `git tag -l` fail breaks every check of tags, not this one's alone; it fails closed here, reading all of history, and a seed of its own can make the gate's readers of git fail loudly.

With `tag.sort=bogus`, `git tag -l` exited 128, check read every commit and reported a released build. Reproduced.

### The tests pinned both reviews' cases but not the Goal

severity: smell
verified: yes
judged: test test_release_refuses_a_build_whose_built_by_git_does_not_read_as_a_trailer, test test_release_refuses_a_build_that_names_no_run_or_a_run_not_committed, test test_release_reads_only_the_builds_since_the_previous_tag, test test_every_problem_of_every_build_is_printed_in_one_release, test test_the_builds_are_read_as_git_reads_trailers

Of fifty wrong implementations the reviewer ran, twenty-five passed. The tests now pin those a real commit or a real repository could reach: `%b` for `%B`, so a `Built-By` under a title with no blank line was no build; the highest tag compared as a string, v0.9 above v0.12 on this repository; `Run` in another case; a submodule or a staged record taken for a committed one; a hash of twelve characters for git's abbreviation; DEL left raw and a backslash doubled; a form feed before the colon. Left unpinned by reason: deduplication within a commit, which the release's own deduplication repeats; the separator, the unfolding and the colon an entry's value follows, which change a quote and not a verdict; reading `--all` or the first parent, which a fast-forward main does not tell apart.
