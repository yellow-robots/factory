## Findings

### A commit the store refuses raises out of the builder, losing the numbers and the exit code

severity: defect
verified: yes
judged: test test_a_commit_the_store_refuses_is_reported_and_the_record_stays

`commit_record` raises `GitError` and `main` called it with no guard, where every other failure of a finished run is caught, `record_diff`'s comment saying "never lose the record". Reproduced by the reviewer with a hook of the store's, `commit.gpgsign` in the host's configuration, a lock left behind and a `.git` that is not git's; and by the attended agent with a lock left behind. The record's path is still the first line printed, but the numbers line, the reason a run stopped and the exit codes the program documents are lost to a traceback, and the record is left staged in the store, so the next run's commit carries it. The build after this one reports the refusal, unstages the record and exits 1.

### A set scores a run whose record the store refused as a run with no record

severity: defect
verified: yes
judged: test test_a_run_whose_record_the_store_refuses_is_scored_from_its_record

`_run_case` reads the record's path from what the builder printed only after `builder.main` returns, so an exception skips it and `evals.main` turns the run into a record of `None`: the row is all zeros where the record on disk is green. Reproduced by the reviewer and again by the attended agent with a lock left in the store: `alpha 1/1 error git exited 1`, the row `1 0 0 0`, the record green on disk. One hiccup of the store's cost a whole run's score, in the direction of looking worse.

### The host's git configuration reaches the store, and a global ignore file drops the wire from the commit

severity: defect
verified: yes
judged: test test_the_store_s_git_is_the_factory_s_alone

`store_env` unset only git's six `GIT_DIR`-family pointers, so the host's system and global configuration decided what a record's commit held: `git add` without `-f` obeys `core.excludesFile`. Reproduced by the reviewer and again by the attended agent with a global ignore file naming `*.log` and `*.gz`: the run exits 0, prints its numbers, says nothing, and the commit holds five files of seven, the check's log and the compressed wire missing. `commit.gpgsign`, `core.hooksPath` and a hook of the store's own break the commit outright, the loud half of the same fault. The build after this one runs the store's git with the system and global files unread, hooks off and `add -f`.

### A `FACTORY_INSTANCE` that is set and empty is read as none named

severity: defect
verified: yes
judged: test test_a_configuration_a_run_cannot_use_is_a_usage_error_before_anything

`if named:` treats an empty value as unset, so a wrapper, a unit file or `env FACTORY_INSTANCE= ...` sends the run to whatever store the home's configuration names. Reproduced by the reviewer, on this instance's own store: reviewing the build that made the store, its probe wrote and committed a record of a scripted run over a checkout in `/tmp`, with a made-up key and no model called. The attended agent removed that record and committed the removal in the store, `20260917T223028Z removed: no run of the factory's`, and reproduced the fault in a temporary home. Every other malformed value is exit 2; this one is exit 0 into another instance's store.

### A configuration whose bytes are not UTF-8 is refused without naming the file

severity: defect
verified: yes
judged: test test_a_configuration_a_run_cannot_use_is_a_usage_error_before_anything

`config.read_text(encoding="utf-8")` raises `UnicodeDecodeError`, which is a `ValueError` and not an `OSError`, so it passes the reader's own refusal and arrives at `main`'s catch bare: exit 2, and the message is the decoder's with no path in it. A TOML file must be UTF-8, so this is the Goal's "is not TOML", which must name the file. Reproduced by the reviewer and again by the attended agent.

### A `records` that cannot hold a record is read as usable and falls over after the key

severity: defect
verified: yes
judged: test test_a_configuration_a_run_cannot_use_is_a_usage_error_before_anything

`record_store` checked the string's shape and never the path: a `records` naming a plain file, a path under a file, or a directory the run cannot write raises `NotADirectoryError` or `PermissionError` from the loop that makes the run's directory, after the key has been read, with exit 1 and a traceback where the seven faults beside it are exit 2 with the file named. Reproduced by the reviewer with three paths and again by the attended agent with a plain file. The build after this one makes the store's directory when the configuration is read.

### The search for the key fails open on anything it cannot read

severity: defect
verified: yes
judged: test test_the_search_for_the_key_does_not_fail_open, test test_a_record_the_search_cannot_read_through_is_a_reported_run

`leaked_file` skips a file whose read raises `OSError` and commits the record: a file with no permission holding the key is not found, and neither is a truncated `.gz`, whose `EOFError` the build before had turned into a read of the compressed bytes, where the key is not to be found. A gzip file named `.GZ` is searched as compressed bytes for the same reason, and a directory reached by a link is never walked into, since `rglob` does not follow one. Reproduced by the attended agent, each case returning `None` with the key inside. The guard that must not fail open was the one that did; nothing the search cannot read through is committed now.

### The table pays the model stack to read one function of the builder's

severity: smell
verified: yes
judged: test test_the_configuration_is_read_without_the_builder

`runs.py` imports `builder` for `record_store` alone, so printing a table of numbers resolves `httpx2`, `pydantic`, `pydantic_ai` and the library's version, inherits every import-time failure of the builder and takes its import-time change to the environment. Measured by the reviewer and again by the attended agent: two seconds against nineteen milliseconds for the standard library alone, and about fifteen hundred modules. The configuration is twelve lines with no dependency on the builder, and the build command will want it too, so it becomes a module of its own.

### The module docstring still lists the plain wire among a record's files

severity: smell
verified: yes
judged: test test_the_record_leaves_no_patch_when_the_run_left_nothing_and_the_text_says_so

The store's builds rewrote where a record is kept and left what it holds: `wire.jsonl (every HTTP attempt as it happened)` where a finished record holds `wire.jsonl.gz` and never the plain file. The two lists in the tests were corrected in the same red commit and this third one was not. Reproduced by reading the docstring; the docstring test now names the compressed wire and refuses both the plain one and `runs/<utc-stamp>`.

### A very short key refuses every run, and an empty key file runs with the wall off

severity: smell
verified: yes
judged: test test_a_key_file_with_no_value_is_a_usage_error

A key of one character appears in every record, so the search refuses to commit it and the run exits 1 after the model was paid for; an empty key is special-cased to hold nothing, so the record is committed with the search doing nothing. Reproduced by the attended agent: a one-character key refuses on `diff.patch`, an empty key file commits every file. The one-character run is the search working and the Goal says so; the empty key file is the hole, and a key file with no value is now a usage error where the key is read, so the special case goes with it.

### The whole wire is held in memory twice

severity: smell
verified: yes
judged: none: measured on the records on file, the largest wire is 21 MB whole and 6 MB compressed against a median of 0.2 MB, in a process that has just held a model session; a streaming read costs nothing in clarity and is the next build's if a wire ever grows by an order of magnitude

`compress_wire` reads the plain wire whole and holds its compressed copy beside it, and `leaked_file` decompresses a `.gz` into one `bytes` to search it. Reasoned by the reviewer, measured by the attended agent over the 149 compressed wires in the store.

### The tests do not pin a message of its own for each fault of the configuration

severity: smell
verified: yes
judged: test test_a_configuration_a_run_cannot_use_is_a_usage_error_before_anything

The tests asserted the configuration's path in every refusal and one word in a few, so a single message holding both words would satisfy all eight; the reviewer showed the mutant green with `record_store`'s six messages replaced by one. The attended agent's test of the three new faults now asks that the four messages differ from one another.

### The tests do not pin that the compressed wire is read through its compression

severity: smell
verified: yes
judged: test test_the_search_for_the_key_does_not_fail_open

The test of a record holding the key planted it in the report, where it lands in three files, and accepted any of them, so a search that skipped every `.gz` passed: the reviewer showed that mutant green. The wire is the one file the Goal singles out and the one place a key would survive a redaction. The new test plants the key in the compressed wire alone and asks for it by name.

### A record's symlinked directory is not walked into

severity: smell
verified: yes
judged: test test_the_search_for_the_key_does_not_fail_open

`rglob` does not follow a symlinked directory, so a link inside a record hides whatever it points at from the search. Nothing can plant a link in a record today: the tools confine the model to the checkout and a record is the builder's own writing. Reproduced by the attended agent all the same, and the wall now refuses a record holding a link rather than walking it, since a record with a link in it is not a record the factory wrote.
