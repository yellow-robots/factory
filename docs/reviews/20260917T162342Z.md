## Findings

### A value git reads over two lines counts as read, and the release tags

severity: defect
verified: yes
judged: test test_the_builds_are_read_as_git_reads_trailers

`_build_trailers` split git's output at every newline, so a trailer continued on an indented line after its run became two values, the line's own value matched the first, and nothing checked git's value, which ends in the continuation and names no run. Reproduced with the reviewer's probe: `Built-By: factory at 1234567, run <stamp>` continued by `  retried after a timeout`, the record committed, gave no problem and the release tagged. The Goal is rewritten whole: git's values are read unfolded and apart at NUL, and every value git reads must end `run <stamp>` as every line's own must.

### A carriage return splits lines, and the release tags

severity: defect
verified: yes
judged: test test_the_builds_are_read_as_git_reads_trailers

`_git_out` read git's output as text, and Python's text mode turns a bare `\r` into a newline before the gate splits it, so a value `run <stamp>\rjunk`, which git reads whole and which names no run, passed and the release tagged, and a body line `notes\rBuilt-By: …`, no `Built-By` line for git, was taken for a build. Reproduced, both. The Goal is rewritten: everything git prints is read as bytes and split at `\n` alone.

### Every commit reads as holding an empty value, so an empty `Built-By:` git does not read counts as read

severity: defect
verified: yes
judged: test test_every_problem_of_every_build_is_printed_in_one_release

`git log --format` ends each commit's output with a newline of its own and `_build_trailers` removed one blank, so a commit with no trailer read as one empty value, and an empty `Built-By:` apart from the trailers matched it: the release printed `names no run` and never `as a trailer`. Found also by the attended agent's probe of the build before this review arrived. Reproduced: `valueonly` prints `\n` for no trailer and `\n\n` for one empty value. The Goal is rewritten: git's entries are `<key>: <value>`, never empty, read apart at NUL with the format's final newline removed, and a build whose `Built-By` lines outnumber the entries git reads is refused.

### Values stripped and the key matched by Unicode rules where git uses ASCII

severity: smell
verified: yes
judged: test test_the_builds_are_read_as_git_reads_trailers

`strip()` removes a no-break space git keeps, so a value git reads was reported as one git does not read, its quote looking like a good value; `re.IGNORECASE` matches `Buılt-By:` with a dotless i, which git does not read as the key. Reproduced. The Goal is rewritten: the key's letters are ASCII of any case, and values are stripped and split at ASCII whitespace alone.

### Commits named by their full hash when `core.abbrev` is 40

severity: smell
verified: yes
judged: test test_release_refuses_a_build_whose_built_by_git_does_not_read_as_a_trailer

`rev-parse --short` follows `core.abbrev`, so with it at 40 or `no` every problem named the full hash, which the Goal forbids. Reproduced. The Goal is rewritten: the hash is git's unique abbreviation of at least seven characters whatever the configuration says.

### Problem lines escape every non-ASCII character

severity: smell
verified: yes
judged: test test_every_problem_of_every_build_is_printed_in_one_release

`_line_text` uses `unicode_escape`, so `café` printed as `caf\xe9` and a backslash doubled, where the docstring said control characters. Reproduced. The Goal is rewritten: control characters escaped, nothing else changed.

### Some git failures after the commits are listed name no commit or read as nothing

severity: smell
verified: yes
judged: test test_a_git_failure_refuses_the_release_and_no_path_hides_the_builds

Injected in the process: a failing `%B` or trailer command printed the command without the commit, one line for any number of commits, and a failing `rev-parse --short` was swallowed. Reproduced with the reviewer's probe. The Goal is rewritten: a failing command is a problem naming the command and the commit it read. Only the listing's failure can be made with a real repository in a test, by a missing commit object; the others stand on the Goal and the review.

### The release reads the builds a second time and never prints it

severity: smell
verified: yes
judged: none: the Goal now says `release` reports them through `check`, which it runs first, and does not read them again; a second read prints nothing whether it is there or not, so no test can see it, and a version named wrongly while another is in flight is reported once `check` is silent, as before this seed.

`main` runs `check` first and stops on any problem, and `check` reads the same builds, so the read in `_release_problems` can only repeat work. Reproduced: removing it keeps every test green.

### The tests pin the first review's fixes but not the Goal

severity: smell
verified: yes
judged: test test_check_reports_a_build_git_cannot_list_before_main_moves, test test_release_refuses_a_build_that_names_no_run, test test_every_problem_of_every_build_is_printed_in_one_release

The reviewer ran eight tests against twenty-four wrong implementations; among those that passed were an indented key taken for a build, a line counted read when another had matched the same value, a symbolic link passing as a record, no deduplication, `check` reading nothing with no version in flight, and the no-tag branch. Reproduced with its probes. The tests now pin each of those; following the first parent alone stays unpinned, main moving by fast-forward only.
