## Findings

### A `Built-By` git does not read is never checked for its run

severity: defect
verified: yes
judged: test test_every_problem_of_every_build_is_printed_in_one_release

`_build_problems` moves to the next value after the problem that git does not read a line, so its run and its record are never looked at, and a release shows one problem where the Goal wants every one. Reproduced with the reviewer's probe: a line apart from the trailers with no record committed gave only `git does not read` on the first release, and `names a run with no committed record` after the trailers were put together; a value naming no run the same. The Goal is amended: every value is checked for its run and its record whether git reads it or not, and one release prints every problem, each once.

### An empty `Built-By:` is called unread

severity: defect
verified: yes
judged: test test_every_problem_of_every_build_is_printed_in_one_release

Git reads `Built-By:` with nothing after the colon as a trailer with an empty value, `valueonly` printing a blank line for it; the gate dropped blank lines and said git does not read it, where the value names no run. Reproduced: `Built-By:` in the trailer block, and `Built-By:` followed by spaces, both refused as `git does not read`. The Goal is amended: the values git reads are kept apart so that an empty one counts, and an empty value names no run.

### A git failure reads as no builds, and the release tags

severity: smell
verified: yes
judged: test test_a_git_failure_refuses_the_release_and_no_path_hides_the_builds

`_git` ignores git's exit status and `rev-list <previous>..HEAD` names no end of options, so a committed file named `v0.1..HEAD` made git refuse the argument as ambiguous, exit 128, the builds read as none, and the release tagged over a line git does not read. Reproduced with the reviewer's probe. A gate that opens when git fails is the wrong way round. The Goal is amended: the commits are listed as revisions whatever paths the checkout holds, and a git command that fails while the builds are read is a problem naming the command.

### Output git gives in another encoding ends the release with a traceback

severity: smell
verified: yes
judged: test test_a_message_git_prints_in_another_encoding_does_not_end_the_release

The release now decodes the message of every commit since the tag, and `_git` decodes strictly, so a repository whose `i18n.logOutputEncoding` is Latin-1 raised `UnicodeDecodeError` on an ordinary `café` commit, no problem lines, where the parent commit's gate released it. Reproduced. The Goal is amended: what cannot be decoded is replaced.

### Values are compared as Python splits lines, not as git does

severity: smell
verified: yes
judged: test test_the_builds_are_read_as_git_reads_trailers

`splitlines()` splits at a form feed as well as a newline: a value `run <stamp>` followed by a form feed and more text was read as naming its run, and a line holding `Built-By:` after a form feed was taken for a build. Reproduced with the reviewer's probe, both ways. The Goal is amended: the message is split at newlines alone. A value folded onto a second line stays refused, its first line naming no run: no commit here folds a trailer, and the refusal is loud.

### A line of prose that begins `Built-By:` blocks a release after main has moved

severity: smell
verified: yes
judged: test test_check_reports_a_build_git_cannot_list_before_main_moves

By the Goal's definition any commit since the tag with such a line is a build, and the release runs after the version's commits are on main, so the only way out would be rewriting main's history. Reproduced: a commit whose wrapped prose put `Built-By:` at a line's start refused the release. The definition stands; the Goal is amended so that `check` reads the same builds and reports the same problems, and a build git cannot list is seen in the version's worktree, where the commit can still be amended, before main moves.

### A file or a link at `runs/<stamp>` passes as a record

severity: smell
verified: yes
judged: test test_release_refuses_a_build_that_names_no_run_or_a_run_not_committed

`ls-tree` lists a blob as readily as a tree, and AGENTS.md and the review check both hold a run to be a directory. Reproduced: a committed file and a committed symbolic link at `runs/<stamp>` gave no problem. The Goal is amended: the record is a tree in HEAD's tree.

### `Built-By` in another case or with a space before the colon is not a build

severity: smell
verified: yes
judged: test test_the_builds_are_read_as_git_reads_trailers

Git's key match, the one AGENTS.md's listing uses, reads `built-by:` and `Built-By :` as `Built-By`, and the gate's `startswith("Built-By:")` skipped both, so a run with no record passed. Reproduced. The Goal is amended: a `Built-By` line begins with the key as git's trailer syntax matches it.

### The tests left most of the Goal unpinned

severity: smell
verified: yes
judged: test test_release_refuses_a_build_whose_built_by_git_does_not_read_as_a_trailer, test test_release_refuses_a_build_that_names_no_run_or_a_run_not_committed, test test_release_reads_only_the_builds_since_the_previous_tag

The reviewer ran the three tests against sixteen wrong implementations and eleven passed. Reproduced with its probe. The tests now pin the highest tag against a lower one, a stamp that is not one path segment, the words of the problems, the abbreviated hash, every problem printed, a record removed from HEAD's tree, and a key matched anywhere in a line. Two stay unpinned, by reason: reading nothing when there is no tag, a branch only a repository's first release reaches and this one has twelve tags; and following the first parent only, since main moves by fast-forward alone and has no merge.
