## Findings

### A failed build says git's whole stderr, on its own and in the note it pushes

severity: defect
verified: yes
judged: test test_a_failed_build_says_one_line_and_the_note_names_the_record_by_its_stamp

The Goal asks for one line of the factory's own words, on stderr and in the note; `GitFailed` carried git's stderr as git wrote it, several lines of it, where the builder's own refusal collapses them. Reproduced by the reviewer with a repository whose `pre-receive` declines and with a `refs/heads` git cannot write, and by the attended agent with the latter: four lines on stderr and the same four pushed as the note on the head the build was asked of. The note carried the store's absolute path as well, which is the instance's business and not the project's. What a failed build says is now one line, the record by its stamp and the reason with git's words on one line.

### The commit a build pushes can hold a file the record's diff does not show

severity: defect
verified: yes
judged: test test_the_host_s_git_configuration_changes_no_record

The store's git ran with the host's system and global configuration unread, the builder's own git with all of it, so the two disagreed about what git ignores: with a global `core.excludesFile` naming `*.log`, a `notes.log` the model wrote was committed and pushed while the record's `diff.patch` never named it and `files_changed` counted one file of two; and a run whose only change was such a file was reported as one that changed nothing, its record holding no diff at all. Reproduced by the reviewer and again by the attended agent, both halves. It is the one breach of the Goal's own wall, which rests on `diff.patch` holding whatever the model changed. Every git the factory runs now reads neither the system's file nor the global one.

### A repository named by a relative path is read from the root

severity: defect
verified: yes
judged: test test_a_relative_repository_is_read_from_the_caller_s_directory

Every git call of the command ran from `/`, so a repository named relatively was refused as one git cannot read, and a path of that name under the root would have been built in its place. Reproduced by the reviewer and by the attended agent: `origin.git` beside the caller is refused where git itself, run there, lists its four refs. A relative path is now read from the directory the command was run in.

### The stamp of a second run in one UTC second names no run

severity: defect
verified: yes
judged: test test_the_stamp_of_a_second_run_in_one_second_is_a_run

The builder names a record whose stamp is taken `<stamp>-<n>`, and the gate's shape accepted the stamp alone, so the command would push a build that the gate refuses at the release, the failure AGENTS.md already records for four commits of v0.7 and v0.8. Reproduced by the reviewer with the clock frozen and by the attended agent on the shape itself. The gate now reads the shape the builder writes; a dash with nothing after it, with something that is not a number, or with a second dash still names no run.

### A seed whose name is empty turns the trailer into the subject

severity: defect
verified: yes
judged: test test_a_seed_whose_name_is_empty_is_no_seed

A seed at `docs/seeds/.md` has an empty name, so the message began with a blank line and the trailer, `git commit` cleaned the blank away and took the trailer for the subject, and git read no trailer at all: another build pushed that the gate would refuse. Reproduced by the reviewer and by the attended agent. Such a seed is now no seed, refused before a model is called, and the seed's path is read stripped as the builder reads it.

### A vault git answers about somebody else is passed over whole

severity: defect
verified: yes
judged: test test_a_vault_git_answers_about_somebody_else_is_read_whole

`_vault_paths` took any answer git gave without asking whether git answered about this directory, so a copy of the vault inside a repository that ignores it had that repository answer, which tracks nothing of the copy: every note was passed over and `check` went silent on a vault with no frontmatter anywhere, the exact promise the accompanying test was written to protect. Reproduced by the reviewer and by the attended agent. git's answer now counts only when its top level is the directory the gate was given, as the builder asks of a checkout.
